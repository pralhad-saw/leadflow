# LeadFlow submission summary

LeadFlow is a multi-tenant lead and document platform for German mortgage brokerages. I implemented JWT authentication, bcrypt password hashing, four role types, brokerage-level data isolation, an authenticated inbound lead webhook, duplicate protection, a Kanban pipeline, advisor assignment and Socket.io live updates. A won lead can be converted into a client account. Clients get their own application portal and can upload PDF or image documents to Cloudinary. Uploaded documents are stored in MongoDB with a Pending status and a fake asynchronous checker changes them to Checking and then Approved or Rejected while broadcasting live status events to the relevant brokerage room.

The intentionally weaker or missing parts are real email automation, automatic task creation, a production message queue, OCR-based document verification, advanced fuzzy duplicate detection and dashboard caching. The document checker uses setTimeout only to demonstrate a slow/flaky workflow; production would use a durable queue such as BullMQ with Redis. JWT localStorage was chosen to simplify the cross-origin demo, but production should use short-lived access tokens with an httpOnly refresh cookie. The next steps would be deployment hardening, audit logs, better document versioning, real verification providers and automated tests for every tenant boundary.
