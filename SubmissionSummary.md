
# LeadFlow - Submission Summary

LeadFlow is a multi-tenant lead and document platform built for mortgage brokerages handling expat home-buyers. I built this application using the MERN stack with a strong focus on **data isolation, real-time collaboration and asynchronous background processing**. The platform enforces strict brokerage-level multi-tenancy where every query is filtered by the authenticated user's `brokerageId`, ensuring one brokerage can never access another's users, leads, clients or documents. I implemented JWT-based authentication with role-based access for **platform admin, brokerage admin, advisor and client**, along with bcrypt password hashing. An authenticated inbound **lead webhook** with secret validation, idempotent handling and duplicate detection helps capture leads automatically from external tools. The core of the platform is an **interactive Kanban pipeline** with advisor assignment, lead-to-client conversion and **real-time updates across all open screens using Socket.io rooms scoped per brokerage**. Converted clients get their own portal to view their application and upload documents to **Cloudinary**. These uploads go through a **simulated slow document verification workflow** that moves each document from `Pending → Checking → Approved/Rejected` and pushes live status updates to both the client and advisor via WebSockets.

Due to the 7-day time window, I made a conscious decision to **prioritize tenant isolation, real-time sync and the end-to-end lead-to-document flow** over building every automation feature. I intentionally left out **email templates with placeholders, email triggers on pipeline stage changes, and automatic task creation with due dates & overdue highlighting** as they would have added significant UI and logic without strengthening the platform's core architecture. The fake document checker uses `setTimeout` instead of a production job queue to demonstrate a **flaky, time-consuming background process**. With more time, I would replace it with **BullMQ + Redis** for reliable and crash-resistant job execution, add **per-tenant webhook rate-limiting**, implement **optimistic locking** to handle concurrent pipeline updates, introduce **asynchronous email delivery with retries**, and add **server-side pipeline analytics**. I also chose **JWT stored in localStorage** to keep the cross-origin Vercel–Render demo simple; in a real production system, I would prefer **short-lived access tokens with an httpOnly secure refresh cookie** for better security.
